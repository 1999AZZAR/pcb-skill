# 让 AI 从头画了块四层板，它差点把 26V 打进屏幕的地线

前段时间想做个条形的 MP3 播放器，ESP32-P4 加一块 3.99 寸 400×960 的 MIPI 长条屏，带触摸、蓝牙、耳机口、侧键。硬件我自己也能画，但这次想试试到底能不能整个甩给 AI——原理图、选料、比价、布局、布线、出制造文件、把购物车摆好，一条龙。

结论先说：能，但真正值钱的不是「它画出来了」，而是**它自己画错、又被自己抓出来的那些地方**。DRC 全绿的板子照样是废板，这句话我以前只是嘴上说说，这次是真吃到了。

流程和工具我整理成了一个 skill 开源出来，Claude Code / Codex 桌面版都能直接用：

https://github.com/daishuge/pcb-skill

下面挑几个我觉得最有意思的坑说说。

## DRC 零错误，但两根网络已经短在一起了

原理图 149 个器件、109 个网络，第一版画完 DRC 报 0 错，肉眼看每根线也都接在该接的地方。

然后网表断言跑出来：`BL_SW`（背光开关节点）被合并进了 `TF_PWR`（TF 卡电源），`I2S_DOUT`、`U0TXD` 全都并进了 `GND`。

原因是我让它用「网络端口」收尾每根信号线，一共 256 个。EasyEDA 在这个规模下解算网表会**静默串网**——不报错，不高亮，DRC 也看不见。换成「网络标志」之后 109 个网络全部正确解析。

这条如果没抓到，做出来就是背光开关直连 TF 卡电源。我现在的规矩是：**网表必须用断言验证，不能用「DRC 过了」代替**。最后那版跑的是 203 条必连 + 37 条必不连 + 18 条必悬空。

## 屏幕排线插不进去，而且「顺手转正」会烧屏

这条是我自己盯着 3D 图问出来的。我问它：屏那个排线是不是反了，这样插得进去吗？

它去把厂家图纸的剖面 A-A 当矢量解出来读——每个触点是音叉形，自由端在焊脚的**对面**，所以排线只能从自由端进。又找了两条独立佐证：装配外框在 +y 方向比三维包络短 0.845mm，正好是焊脚的突出量；而 +y 那一面的凹口只有 15.05mm 宽，装不下 15.50mm 的排线。

结论是座子整个转了 180 度，插口朝着 USB-C 那一端，而排线从屏那一端折过来，指尖停在 y=49.255，**正好压在座子 2mm 厚的壳体上面**。完全接不上。

更阴的是第二层：当时的引脚映射是**对的**——但只要有人「顺手把朝向转正」而不同时改封装编号，映射就会整体镜像，22.4–26.4V 的背光正极会直接落到屏的地线上。修法是一次提交里做四件事（重编号 + 丝印镜像 + 转向 + 走线延长），因为重编号正好抵消转向带来的端头对调，是平移不是排列。

## 3D 检查验了整整一个版本的旧板子

这个是工具自己的问题，也是我最喜欢的一条。

3D 干涉检查的脚本用 pickle 缓存了网格，缓存 key 没带版本。结果是**整整一个 release 都在验上一版的板子**，一路报「零干涉」。

修好重跑，立刻发现三个元件卡在耳机座实体里面——因为耳机座的实体比它的装配外框大 3.05mm。

同一批还查出另外三个静默失效：多边形距离函数对「完全包含」视而不见（一个焊盘被候选外框整个吞掉，它读成 0.22mm 净空）；模组本体检查只测面积大于 20mm² 的，所以 0603 可以合法地摆在钽电容底下；铺铜光栅化会从平面自己的零宽度开口漏出去，导致**这个项目所有的 Gerber 间距数字都是在合并标签上量的**。

所以后来加了一条：**先验工具，再信结果**。任何几何变换在用于判定之前，必须拿一个已知的不对称物体标定——用对称样本验证镜像等于没验证。

## 其它几个

- **一颗 0805 电容整个落在蓝牙模块本体底下**。模块只在一条边上 11 个焊盘焊接、悬空 23.7mm，装上去要么翘 22 度要么把电容压碎。
- **电池插头够不到**。侧插座的插口深 5mm，PHR-2 插头要伸出 1.85mm，但 1.33mm 处就撞上两颗电容。而且买的电芯是裸线没插头，侧插贴片座又没法直接焊线。最后干脆把座子删了，换成两个裸焊盘直接焊线。
- **天线禁布区是假的**。它只是文档层上画的一个框。把 Gerber 光栅化去数，天线端下面四层都有铺铜、覆盖率 93.8%，还压着 10 个接地过孔。
- **电源铜过流 2.5 倍**，还有 48mm 热铜正好压在锂电池上方。典型负载温升 25–31°C，最坏 179°C。
- **耳机检测脚超绝对最大值**。那个耳机座第 3 脚是常闭簧片压在左声道信号上，所以不插耳机时检测脚就是音频信号本身，每个负半周把 IO 拉到 −1.04V，而极限是 −0.3V。
- **充电芯片被设成 500mA，但它物理上做不到**。热阻 250°C/W、结温上限 110°C，封装最多耗 0.34W，实际只能到 140–260mA，而且整个充电过程芯片顶在 110°C——还是在密封外壳里。

## 还有一次卡了 10 小时 53 分

自动布线跑到一半崩了，JVM 挂着 0% CPU 不退出。我的等待条件写的是「SES 文件出现 **或** 进程退出」——两个都没触发。崩溃日志从头到尾就在那儿躺着。

现在的规矩是：**等待条件必须能回答「如果它现在就崩了，我的过滤器会不会吐出一行？」**。看门狗要覆盖四个终止状态：输出出现、日志里有崩溃特征、进程消失、墙钟超时。再加一条速率地板——连接数/分钟低于本次运行自身中位数的 10% 持续 15 分钟就杀掉。

## 关于「让 AI 干完」这件事

我中途跟它说了句「后面别再问我了，你自己定，一路推到底」。它的做法是：所有取舍自己拍板，但每个决定都带着测量数据写进一个决策日志，我事后想推翻随时翻得到、也看得见它当时凭什么这么定。有几次它还顶着我给的建议改——比如我按体检报告让它把某个分压改成 2.2k，它算出电池掉到 3.0V 时输出只有 2.062V、而芯片要 2.475V 才认高电平，低电量时蓝牙串口会哑掉，就自己改成了 10k 串联。这种我认。

## 说点不好听的

**这块板还没做出来，也没上电。** 上面所有的「抓到了」都是设计阶段的抓获，不是实测结果。真做出来大概率还有一堆现在看不见的问题。

成本上，第一版整个报废——布线跑到 11% 就再也推不动了，根因是摆放间距只有 0.55mm，两根 0.10mm 的线塞得进去，但一个 0.50mm 的过孔需要 0.704mm，永远塞不进。制造文件也前后作废了两次。

最后这版 41.4×100mm、四层、149 个件全手焊，元件加板子一共两百多块，板子本身走的免费打样。

## 开源了什么

https://github.com/daishuge/pcb-skill （MIT）

- `skills/pcb/` —— skill 本体 + 七篇按需加载的参考：工作流与关卡、对抗评审协议、嘉立创制造和免费券条款（带原文引用）、选料与比价、KiCad 自动化与工作流指南、机械/3D 验证、烧录与上电
- `scripts/` —— 21 个检查器。它们**解析导出文件和 Gerber，不问 EDA**，所以能反驳生成它的工具。上面那四个静默失效全部修好了，其中三个带 selftest 复现当年的错答案
- `setup/` —— KiCad 环境配置、浏览器登录、Windows/macOS 的审批弹窗看门狗
- `docs/case-study.md` —— 这块板的完整复盘
